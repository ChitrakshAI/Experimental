# Daily check

Ten minutes inside the 30-minute routine. Same time every day, ideally overlapping the US morning so that sub-5-minute proposal speed on fresh US posts is achievable in the same sitting.

The point is a **continuous series, not a perfect one**. A gap in the series is worse than a day of rough numbers, because a gap cannot be compared to anything.

Collect, log, act on anything urgent. Decisions wait for the weekly review. The daily loop collects, the weekly loop decides, and keeping them apart is what stops one noisy day from becoming a strategy change.

Every metric, benchmark and threshold below is verified in `research/marketplace-expansion.md` section 6 and `research/fiverr-market.md` section 4.1.

## 5. Log it

One command per gig, with the account-level fields on the first one only so they are not double counted in the weekly rollup.

```bash
cd marketplace-hub

python3 hub.py metrics add --platform fiverr --account hanfluxai --gig gig1 \
  --impressions 412 --clicks 9 --orders 0 --messages 2 \
  --response-rate 100 --response-time-h 0.4 --success-score 0 --rating 0 \
  --cancellations 0 \
  --source fiverr-gig-analytics --note "day 3 after publish"

python3 hub.py metrics add --platform fiverr --account hanfluxai --gig gig2 \
  --impressions 208 --clicks 3 --orders 0 --messages 0 \
  --source fiverr-gig-analytics
```

Upwork is one account-level snapshot, no gig:

```bash
python3 hub.py metrics add --platform upwork --account TODO-frankie \
  --proposals-sent 4 --proposals-viewed 3 --interviews 1 --hires 0 \
  --boosted-proposals 1 --connects-spent 42 --connects-balance 318 \
  --profile-views 11 --invitations 0 --jobs-identified 5 \
  --source upwork-stats-and-trends
```

On JSS refresh days, add `--jss 100` and `--earnings-12mo 450`. Between refreshes, **leave them off**: re-logging an unchanged 14-day-old figure every day makes a stale reading look like a fresh one.

Ad spend goes through the ads command so it lands against a named campaign:

```bash
python3 hub.py ads log --campaign gads-search-intent --spend 4.80 --clicks 2 --impressions 61
```

**Mechanics worth knowing:**

- `--date` defaults to today. Pass it explicitly when catching up on a missed day, and only when the figures are genuinely still visible in a 48-hour view.
- CTR is computed from impressions and clicks if `--ctr` is not passed. Conversion rate is computed from clicks and orders the same way.
- A second snapshot for the same date, platform, account, gig and source is the correction path, and the reader takes the last line. **A correction must reuse the same `--source`.**
- An identical repeat is detected and skipped, so re-running after a typo elsewhere is safe.
- **Leave a field off rather than guessing it.** An empty cell is a known unknown. A guessed number is a false reading that will be compared against next week. Do not pass zero to mean unknown: zero is a reading.

## 6. Leading-indicator thresholds, checked every day

These are the seven ranked indicators from `STRATEGY.md` section (i). `hub.py metrics report` flags them automatically, but the daily check is where they are seen first.

| # | Indicator | Act at | Action |
|---|---|---|---|
| 1 | Upwork proposal view rate | Below 30% on 10+ proposals | The first two lines and the profile headline. Fixable the same day |
| 2 | Upwork interview rate | **Below 5% after 20 proposals** | Stop bidding for one day, rewrite the two opening lines, record a new Loom, resume |
| 2 | Upwork interview rate | **At or above 13%** | The template works. Raise volume before changing anything else |
| 3 | Fiverr CTR | Below 2% with 200+ impressions | Thumbnail first, then title. No impressions at all means the category and tags are wrong instead |
| 4 | Response time | Above 1 hour | Same day. It is a direct ranking input on both platforms and it costs nothing |
| 4 | Response rate | Below 90%, urgently below 80% | Level 2 needs 90%, Level 1 needs 80% |
| 5 | Upwork invitations | Zero across 14 days of Availability Badge spend | Turn the badge off |
| 6 | Fiverr conversion rate | Below 2% with 30+ clicks | Packages, ladder or description. Not discovery |
| 7 | Qualifying jobs identified | Below 3 a day | The niche filters are wrong. Proposal quality cannot compensate |

## 7. Act on these today, not at the weekly review

| Seen | Do now |
|---|---|
| An unanswered message | Answer it. The SLA is 60 minutes between 08:00 and 23:00 IST, 8 hours overnight |
| An order due within 24 hours | Confirm it will land. Never let a clock run out silently |
| A cancellation | Log it with the reason. On Upwork, never initiate one: negotiate a reduced-scope close instead |
| A platform warning or policy notice | Read it fully, log it verbatim, and change whatever caused it before doing anything else |
| A blocker cleared, for example verification passed | Close it in the ledger |
| Ad spend with zero clicks | Pause the campaign, then diagnose |
| Interview rate under 5% over the last 20 proposals | Tomorrow is a rewrite block, not a bidding block |

```bash
python3 hub.py log --platform fiverr --account hanfluxai --entity blocker \
  --ref id-verification --action closed \
  --detail "ID verification passed" --actor chitraksh
```

## 8. Close the loop

```bash
python3 hub.py status
python3 hub.py next
```

Read the overdue flags and the one next action per account. If something is overdue, either do it or re-due it with a real date. Do not scroll past it.

---

## 9. The honesty rule

If a number was not read today, it does not get logged today. Carrying yesterday's figure forward, or interpolating a missed day, corrupts every week-over-week delta that follows and there is no way to tell later which rows were real.

A missed day is a missed day. Leave the gap and note it.
